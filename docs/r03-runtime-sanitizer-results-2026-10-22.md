## Expat disposition proposed for independent review

CPython 3.12.15's [bundled header](https://github.com/python/cpython/blob/v3.12.15/Modules/expat/expat.h) identifies 2.8.5, agreeing with execution. The [2.9.0 maintainer release](https://blog.hartwork.org/posts/expat-2-9-0-released/) lists two further issues. **No 2.9.0 patch/backport is claimed for this binary.**

- **CVE-2026-102633:** upstream describes a 32-bit allocation overflow. The selected interpreter is x64; propose architecture non-applicability for this exact input.
- **CVE-2026-77214:** upstream fixes invalid `XML_ParseBuffer` lengths beyond available capacity. In [CPython's wrapper](https://github.com/python/cpython/blob/v3.12.15/Modules/pyexpat.c), normal Parse uses actual bounded input lengths. ParseFile obtains a fixed-size buffer; `readinst` rejects oversized bytes/bytearray results before copying or passing the actual count. [ElementTree](https://github.com/python/cpython/blob/v3.12.15/Modules/_elementtree.c) uses the Parse capsule API. Benign actual-runtime checks confirm oversized Python file-reader rejection, ordinary Parse/ParseFile/ElementTree success and malformed UTF-16 rejection. Propose bounded-caller non-applicability for these consumers; this is source inference supported by wrapper probes, not direct native exploit testing or proof of patched Expat internals.

The app's PDF text workflow does not request XMP, as earlier investigated. No arbitrary native-plugin feature is added. Reassess dispositions if consumers or architecture change. Expat's upstream changelog also carries an [unfixed-issues warning](https://github.com/libexpat/libexpat/issues/1160); neither 2.8.5 nor a literal 2.9.0 label earns blanket clearance. Exact compiled/native provenance, advisory refresh and relevant final-package coverage remain open. If the proposed dispositions are rejected, select a verified compatible patched build or supported backport before release.
